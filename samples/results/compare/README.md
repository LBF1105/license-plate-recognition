# 演示用对比图

这个目录是给汇报 / PPT 用的，图片与 `samples/results/` 下的同名文件一致，只是按用途重命名并编了号。

生成来源：`scripts/run_two_stage.py` + `scripts/train_corner_net.py` 的实测结果，300 张 CCPD + 8 张自采湘牌。

---

## 建议的使用顺序

### 讲"问题是什么"

**04_问题成因_裁剪图与拉伸图.png**

左列是 YOLO 按轴对齐框裁出来的图，右列是真正送进 LPRNet 的 168×48 图（放大 4 倍）。
能直接看到：车牌歪的时候，裁剪框带回大量背景，字符被横向拉宽（最严重的一例拉宽 45%）。
配合一句「YOLO 的检测头只输出水平矩形，表达不了旋转」即可。

### 讲"我们试过什么、为什么不行"

**05_方法对比_假顶点与真顶点.png**

三列并排：①原图 ②用宽高比反推的假顶点拉正（车牌被转出画面）③用真值顶点拉正（笔直清晰）。
这张最适合讲"错在哪"——同一张图，顶点错和顶点对，结果天差地别。

**06_失败反例_假顶点拉坏.png**

8 个「原本识别正确、被假顶点拉正后识别错误」的例子。
如果 PPT 里要讲迭代过程，放这张说明纯几何方法为什么被放弃。

### 讲"怎么解决的"

**03_顶点精度_预测与真值叠加.png**

绿框 = 网络预测的四个顶点，红框 = CCPD 标注的真值顶点，两者几乎完全重合。
角点误差中位 0.71%（相对车牌宽度），100% 的样本误差小于 3%。

### 讲"效果"

**01_拉正效果_自拍8张.png**

自采的 8 张湘牌，每行标注：真值 / 原图识别结果与置信度 / 拉正后识别结果与置信度 / 最终采纳哪个。
其中 `xiang_04`、`xiang_05`、`xiang_08` 三张是靠拉正救回来的，其余原图本来就对。
最终 7/8（原本 4/8）。

**02_拉正效果_CCPD修复案例.png**

CCPD 300 张里 8 个「原本识别错、拉正后识别对」的案例，标注了车牌倾角与角点误差。
覆盖 +22°、+20°、+18°、+11°、+9°、+7°、+6° 各种角度。
整体正确率 91.0% → 94.7%。

### 备用

**07_单图候选_xiang05.png** — 单张图的三个候选并排，尺寸 2080×244，适合放在窄条或页脚。

**08 / 09 / 10 早期方案的图** — 几何反解、字符矩形、颜色四边形三种失败尝试的可视化。
只有讲"研发过程"时才用，讲"最终方案"时不必放，容易让听众混淆。

## 关键数据（可直接抄进 PPT）

| 指标 | 拉正前 | 拉正后 |
| --- | --- | --- |
| CCPD 300 张整牌正确率 | 91.0% (273/300) | **94.7% (284/300)** |
| 倾斜 6–15°（56 张） | 82.1% | **92.9%** |
| 倾斜 >15°（8 张） | 62.5% | **87.5%** |
| 自采湘牌 8 张 | 4/8 | **7/8** |
| 角点误差（中位） | — | **0.71%** |
| 单张耗时 | 41 ms | 40 ms |
| 角点网络体积 | — | 2 MB |

补充：
- 对比的基线是「原图直接识别」，两路都做 CTC 置信度择优，保证只赚不赔；
- 5 折交叉验证（模型未见过该折数据）端到端同样是 94.7%，排除过拟合；
- 剩余错误中一半以上是省份字混淆（川→浙、皖→赣、藏→苏等），属识别器形近字问题，与几何校正无关。
