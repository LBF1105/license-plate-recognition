# 自动拉正（deskew）：不动标注，让歪车牌自己变正

分步式方案里，YOLO 输出的是**轴对齐矩形**（AABB，四个数 `x1,y1,x2,y2`）。
它数学上无法表达旋转，所以车牌一歪，框里就会同时装进：

- 车牌本体（歪的）
- 车身的漆面、保险杠、阴影
- 车牌周围的一圈背景

裁剪图随后被直接 `cv2.resize` 到 168×48 喂给 LPRNet，等于把歪掉的字符再横向压扁一次。
在 `data/test_images` 的 300 张 CCPD 样本上，这个损失非常直观：

| 场景 | 图片数 | 整牌正确率 |
| --- | --- | --- |
| 基本水平（偏移 ≤5°） | 175 | 97.1% |
| 轻微倾斜（6–15°） | 90 | 90.0% |
| 明显倾斜（>15°） | 35 | 62.9% |

> 倾斜角由 CCPD 文件名里的 tilt 字段给出，**只用于事后分桶统计**，
> 识别链路本身从不读取文件名，也不使用任何标注。

本模块要解决的就是这一件事：**只凭裁剪图自己的像素**，把歪的车牌拉正。

---

## 1. 两条路径

实现在 `src/plate_recognition/two_stage/deskewer.py`。

### 路径 A：颜色 + 四边形（主路径）

1. `_color_mask`：转 HSV，按中国车牌底色分三段取前景
   - 蓝牌 `95 ≤ H ≤ 135, S ≥ 60, V ≥ 40`
   - 绿牌 `35 ≤ H ≤ 95, S ≥ 55, V ≥ 40`
   - 黄牌 `10 ≤ H ≤ 38, S ≥ 70, V ≥ 90`

   再做闭运算（核长取短边的 5%）补上字符造成的中空，然后 3×3 开运算去噪。
2. `_pick_region`：取面积占比 ≥ 20% 的最大外轮廓，就是车牌。
3. `_contour_to_quad`：先试 `approxPolyDP(0.02·周长)`，正好 4 点且凸 →
   直接用这个四边形（**能表达透视**）；否则退化为 `minAreaRect`
   （把 w/h 摆成宽>高，角度归一到 `[-45, 45)`）。
4. `_evaluate`：像不像车牌，四条硬约束
   - 面积占比 ≥ 0.20
   - 宽高比 ∈ [1.9, 6.5]（普通牌约 3.1，双层牌更高）
   - 对边长度相对误差 ≤ 0.30（否则说明四边形拟合歪了）
   - 倾角 ≤ 40°
5. `_warp_to_frontal`：`getPerspectiveTransform` + `warpPerspective`，
   目标宽高取四边形自身边长均值（不强套固定比例，避免二次拉伸）。
   **并且把四边形围绕质心向外扩 3%~5% 再变换**——这一步至关重要，见 §3。

### 路径 B：梯度投影 + 角度搜索（兜底，默认关闭）

白牌、深色牌、逆光、偏色时颜色先验失效。此时把 `|Sobel-y|` 边缘图按角度
旋转、做行投影，车牌摆正时行能量最集中（投影方差最大），取该角度整图旋转。

实测这条路**精度不够且容易把原本认对的图转坏**：在 300 张上单独用它，
>15° 场景从 62.9% 掉到 40%。原因有两个：

- 行投影对"车牌框 + 字符横笔画"的区分度不足，2° 步长也常常过转（真实 8° 估成 16°）；
- 旋转必然重采样，倾斜车牌本来就分辨率有限，插值后笔画糊成一团。

因此 `enable_rotate` 默认 `false`。它仍然保留在代码里，需要时可打开。

## 2. 关键设计：不做「替换」，只做「多一个候选」

第一版实现是**直接替换**：拉正成功就用拉正图去识别。结果是净亏 14 张：

| 指标 | 不拉正 | 直接替换 |
| --- | --- | --- |
| 整牌正确率 | 91.0% (273/300) | 86.0% (258/300) |
| >15° 场景 | 62.9% | 40.0% |

看失败案例，问题集中在**四边形边界正好压在首尾字符上**：

- 丢字符：`皖ASG102 → 皖AS102`、`皖A1G855 → 皖A1G85`、`皖AF3437 → 皖AF343`
- 多字符：`皖AN2906 → 皖12N2906`、`皖ADE797 → 皖1ADE797`、`皖AZ056U → 皖AZQ56U`
- 完全跑偏：`皖AC0128 → 粤C2`、`皖AM1A66 → 粤L88XLG`
- 省份被削：`皖AWA597 → 陕AWA597`、`皖AX6D99 → 陕AX6D99`

CTC 解码对**长度**极其敏感：切掉一个尾字符，整牌就错了；多带一个伪字符，整牌也错了。
而 LPRNet 本来就是在 CCPD 的宽松 AABB 裁剪上训练的，对"多带一点背景"完全耐受。

于是改成现在的做法：

```
YOLO 框 → 裁剪（外扩 5%）
            ├── 候选 0：原图                     ─┐
            ├── 候选 1：颜色四边形拉正（外扩 3%）  ├─→ 各自 LPRNet 识别
            └── 候选 2：颜色四边形拉正（外扩 5%）  ─┘        │
                                                             ▼
                                        取 CTC 置信度最高者作为最终结果
```

置信度定义在 `PlateRecognizer.recognize_with_score()`：CTC 贪心解码后，
**每个被保留字符位置的 softmax 最大概率取平均**。这是模型对自身输出的自评，
不依赖任何标注，天然适合在多个图像候选之间择优。

效果：**只赚不赔**。拉正版本只有在模型确实更有把握时才会被采纳，
原本认对的图不会被改坏。

## 3. 外扩（padding）为什么是必须的

透视变换的目标宽高直接取四边形边长，等价于"紧贴车牌边界"。
但颜色 mask 受反光、阴影、铆钉影响，边界常比真实车牌内缩 1–3 像素；
这 1–3 像素在 168 宽的输入上会被放大成半个字符的宽度。

`_warp_to_frontal(..., pad)` 把四边形绕质心放大 `1+2·pad` 后再变换，
结果自然带上一点车牌外框和背景。实测外扩量对结果很敏感：

| 外扩 pad | 触发张数 | 整牌正确率（直接替换） |
| --- | --- | --- |
| 0.02 | 64 | 90.0% |
| 0.03 | 81 | 91.0% |
| 0.05 | 64~81 | 89.7% |
| 0.08 | — | 88.3% |
| 0.12 | — | 86.7% |

太小编号不够（仍会切字），太大把背景和相邻字符带进来（多字符）。
`candidate_pads = (0.03, 0.05)` 同时生成两个候选，让识别器自己挑，
比手工调一个"最佳 pad"更稳。

## 4. 实测结果

同一检测器（`weights/plate_detect.pt`）、同一识别器（`weights/lprnet.pth`），
唯一差别是有无自动拉正；300 张 CCPD 模糊子集。

| 指标 | 不拉正 | 自动拉正（候选+择优） | 变化 |
| --- | --- | --- | --- |
| **整牌正确率** | **91.0%** (273/300) | **92.0%** (276/300) | **+3 张** |
| 字符准确率 | 97.6% | 98.1% | +0.5 个百分点 |
| 检出率 | 100% | 100% | — |
| 平均耗时 | 41 ms/张 | 45 ms/张 | +4 ms/张 |

分场景：

| 场景 | 图片数 | 不拉正 | 自动拉正 | 变化 |
| --- | --- | --- | --- | --- |
| 基本水平（≤5°） | 175 | 97.1% | 97.1% | ±0 |
| 轻微倾斜（6–15°） | 90 | 90.0% | 90.0% | ±0 |
| **明显倾斜（>15°）** | 35 | 62.9% | **71.4%** | **+3 张** |

拉正触发 51/300（17.0%）：`color-quad` 29 张、`color-minrect` 22 张，
平均估计倾角 6.5°、最大 22.3°。
逐张看：**修好 3 张、变差 0 张**。

修好的三张：

| 图片 | 真值 | 不拉正 | 拉正后 |
| --- | --- | --- | --- |
| 0326412835249-92_72-… | 皖A056X8 | 使C3F618 | 皖A056X8 |
| 0398275862069-99_62-… | 皖A97W39 | 皖1S1W39 | 皖A97W39 |
| 0426101532567-112_59-… | 皖AV109N | 皖AV109H | 皖AV109N |

可视化见 `samples/results/deskew_showcase.png`，完整逐张报告见
`samples/results/deskew_report.md`（由 `scripts/compare_deskew.py` 生成）。

### 结论怎么读

- **绝对增益不大（+1 个百分点），但方向是对的**：所有收益集中在 >15° 场景（+8.5 个点），
  其余场景零退化。这正是「只在该拉正时才拉正」应有的形状。
- **LPRNet 本身对轻中度倾斜相当鲁棒**，因为它就是在 CCPD 的歪框裁剪上训练的。
  所以"倾斜 → 识别差"里只有一部分能靠几何校正救回来；剩下的是分辨率不足、
  运动模糊、省份字本身难分（琼/鲁、川/浙、皖/陕）。
- 想继续往上走，该动的是**检测头**（YOLOv8-OBB 直接输出带角度框）或
  **省份字后处理白名单**，而不是继续加几何校正。

## 5. 怎么用

默认开启（`config/config.yaml`）：

```yaml
two_stage:
  preprocessing:
    deskew:
      enabled: true                # 是否对每个车牌裁剪图做自动拉正
      strategy: best_of            # 原图与拉正版一起识别、按 CTC 置信度择优
      max_angle: 40                # 颜色四边形路径允许的最大倾角（度）
      min_apply_angle: 2           # 倾角小于该值时不生成拉正候选（AABB 已足够好）
      candidate_pads: [0.03, 0.05] # 透视变换时的外扩比例，多个值 = 多个候选
      enable_rotate: false         # 梯度投影旋转兜底路径（实测噪声大，默认关）
```

命令行开关（覆盖配置）：

```bash
# 开启（默认即开启，显式指定便于脚本化）
python scripts/run_two_stage.py --source data/test_images --deskew

# 关闭，回到"纯 AABB 裁剪"
python scripts/run_two_stage.py --source data/test_images --no-deskew
```

复现对比实验：

```bash
python scripts/compare_deskew.py --source data/test_images
# → samples/results/deskew_report.md
```

代码中直接使用：

```python
from plate_recognition.two_stage.deskewer import PlateDeskewer

deskewer = PlateDeskewer()
for cand in deskewer.candidates(crop):        # 第一个恒为原图
    plate, score = recognizer.recognize_with_score(cand.image)
    ...                                       # 取 score 最高者
```
